# 产品愿景：VibeBoard AI Agile

## 背景

vibe coding 让个人和小团队可以用自然语言快速推进产品想法，但也带来了新的管理断层：idea、prompt、Agent 动作、代码变化、运行结果、测试失败和 Review 决策分散在聊天窗口、IDE、终端和 PR 里。传统敏捷工具负责追踪“意图”，代码工具负责呈现“现实”，两者之间缺少一层面向 AI 协作的交付追踪界面。

VibeBoard 的机会是把敏捷看板变成 vibe coding 的运行时协作界面：任务卡片不再只是文本，而是能展示用户意图、AI 执行日志、上下文资产、运行预览、验收结果和视觉/行为差异的活体对象。

## 目标用户

- 独立开发者 / Founder，用 AI 快速把想法变成可验收版本。
- 小型全栈团队，需要透明追踪人类和 AI Agent 的贡献。
- 技术 PM / 产品负责人，不想读代码但需要判断任务是否真的可用。
- AI Agent Operator，同时管理多个 coding agent，需要看到计划、动作、阻塞点和结果。
- 外包 / 远程协作团队，需要把“AI 做了什么、是否可验收”变成可复盘证据。

## 产品原则

1. **运行证据优先于文字状态**：Done 不是卡片拖到 Done，而是计划、变更、预览、测试和验收都可追踪。
2. **人类负责判断，Agent 负责执行**：人类定义意图、挑选方案、纠偏和批准；Agent 拆解、实现、测试、记录。
3. **每次 AI 执行都必须可追踪**：prompt、计划、文件、命令、测试、失败、修复和决策都进入 timeline。
4. **验收要尽量可执行**：自然语言标准要转成 DOM、接口、截图、日志或测试检查，减少“看起来完成了”的假象。
5. **上下文会复利**：成功任务沉淀 Context Pack，让后续 vibe coding 更快、更稳、更少跑偏。

## 差异化

| 传统 Jira / Linear | VibeBoard |
| --- | --- |
| 卡片描述工作 | 卡片追踪从 idea 到验收的完整 vibe loop |
| 状态人工维护 | 状态由 Agent timeline、运行证据、检查和 Review 共同驱动 |
| PR 之后才看到结果 | 卡片内持续沉淀预览、日志、测试和差异证据 |
| PM 依赖开发解释 | PM 直接按验收标准和运行证据做判断 |
| Agent 是外部执行器 | Agent 是看板里的可观测队友 |
| 只管理 issue | 管理 prompt、上下文、执行、纠偏、验收和复盘 |

## 北极星指标

- 从 idea 创建到第一个可验证证据的时间。
- AI 任务从 Ready 到 Review 的成功率。
- 验收标准自动检查覆盖率。
- Review 平均耗时。
- AI 任务被人类大幅重写 / 回滚的比例。
- Context Pack 被复用后带来的任务成功率提升。
